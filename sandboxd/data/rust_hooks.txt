# Rust standard-library functions worth an entry-only hook, for Linux ELF
# and Windows PE samples (sandboxd/samplehooks.py, sandboxd/stagehints.py).
#
# A line is a template, NOT a directly loadable apimon/libmon entry:
#   rust,<demangled Rust path>,no-retval,log
#
# `samplehooks` locates raw (mangled) function symbols via ELF symbol tables
# or Rust FLIRT sets, demangles Rust v0/legacy names with `c++filt -s rust`
# (GNU binutils), and matches the paths below. It then emits an offset hook
# in the sample's own module; the `rust` pseudo-module is never sent to DRAKVUF.
# `no-retval,log` records the call only: Rust's own ABI is not stable, and
# argument types can differ between compiler versions / monomorphizations.
#
# Do NOT hook high-frequency read/write/alloc, memcpy, or panic functions:
# enormous event volumes. Prefer OS-level API/syscall tracing for detailed
# filenames, network endpoints, buffers, and process arguments.
#
# Some std functions below are generic (e.g. `read<P>`): their copies are
# generated inside each sample, not present in compiler std `.rlib` sets.
# They can still be found when its symbol table is present, or if separate
# project-specific FLIRT signatures identify them. An entry is NOT a promise
# that every stripped Rust binary contains a matching symbol or bytes.
