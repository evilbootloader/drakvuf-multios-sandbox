# Password hashing for the credentials this platform issues itself (DRAFT-061
# decision 3). argon2id, and the parameters are NOT left to the library's
# default: `config.Settings` derives them from `RFC_9106_LOW_MEMORY` -- 64 MiB,
# t=3, p=4 -- and caps concurrent hashes, because each one holds its memory cost
# for the whole hash and a burst of logins allocates all of them at once. That
# is a memory bound a rate limiter cannot enforce; see `rate_limit.count` in
# migration 0009.
#
# The module is `argon2`; `argon2-cffi` is only the distribution name.
# `argon2-cffi-bindings` is pinned beside it deliberately rather than floated as
# a transitive: it carries the compiled Argon2 reference implementation, so it
# is the one to look at on a rebuild that behaves differently.

# uvicorn does NOT implement the WebSocket protocol itself. Without one of
# these it does not handle an upgrade at all: the request is treated as a plain
# HTTP GET, no HTTP route matches the socket path, and the client gets a 404
# from uvicorn with the route perfectly well registered (DRAFT-056, F6).
#
# That failure is invisible to the test suite, because TestClient speaks ASGI
# directly and never goes through uvicorn's protocol layer -- so a WebSocket
# test can pass while the deployed server cannot serve one.
#
# 16.1.1 rather than 17: sandboxd uses the same library on Dom0, whose Python
# is older than this container's, and 17 has no distribution for it. Pinning
# what the DEVELOPMENT container happened to have made an install that could
# not succeed on the machine it was for. One version both hosts can take is
# worth more than the newest one here.
